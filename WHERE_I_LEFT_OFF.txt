===============================================================================
 THE THREE FILTERS ON THE REAL ARTICLES  (all deliberate, do not undo)
===============================================================================

1. REUTERS EXCLUDED. It is 25-35% of All the News 2.1 — the exact flaw being
   fixed.

2. WASHINGTON POST EXCLUDED. Its article bodies are EMPTY in that collection,
   median 0 characters. Nothing to do with the paper itself.

3. GENERAL NEWS ONLY, NOT TECH OR CELEBRITY. This one is subtle and matters.
   The fake articles are conspiracy and junk-science pieces, i.e. mostly
   politics and health. If the real articles were tech blogs and celebrity
   gossip, the model could score well by learning "tech topic = real, politics
   topic = fake". That is topic-matching, not reading, and it would collapse on
   exactly the political stories the exam is made of.
   The 15 kept: CNN, The Hill, Politico, Axios, NYT, Vox, CNBC, Economist,
   Buzzfeed News, Business Insider, Vice, Vice News, Fox News, New Republic,
   New Yorker.
   Use --all-outlets if you ever want to test the idea yourself.


===============================================================================
 THINGS THAT WENT WRONG, AND WHAT THEY TAUGHT
===============================================================================

THE CUTOFF SEARCH COULD NOT REACH THE SCORES  (19 Aug, fixed)
  tune_cutoff.py searched 0.05, 0.06 ... 0.95. But that model was so confident
  that 84% of articles scored above 0.95 — the whole decision happened between
  0.9997 and 0.99996. Every rung of the ladder sat below the entire
  distribution, so it reported 62.37% for a model worth 76.33%.

  THE CLUE: the sorting score went UP 9.6 points while accuracy went DOWN 5.6.
  Those cannot both be true. Suspect the search, not the model.

  Fixed with cutoff_candidates(), which draws candidates from the score
  distribution itself.

round(cutoff, 2) WROTE 1.0 INTO cutoff.json  (19 Aug, fixed)
  The real cutoff was 0.99993797. Rounded to 2 places that is 1.0, and no
  article can score above 1.0, so the app would have answered 'Likely Real' to
  every single article, silently, forever. Cutoffs are now stored as exact
  floats; only display percentages get rounded.

THE ROWS API RATE LIMIT  (20 Aug, handled)
  The Hugging Face rows API returns HTTP 429 after about 36 requests in 45
  seconds — roughly 0.8 per second — with no Retry-After header to obey.
  Five concurrent workers lost 1,107 of 1,300 pages and produced a useless
  file, 68% of it from three outlets.
  Fixed by measuring the limit and pacing under it: MIN_INTERVAL = 1.4 seconds
  in fetch_diverse_reals.py, plus a --merge flag so several runs accumulate
  rather than one long fragile run.

TRAINING ARGUMENTS KEYWORDS DRIFT  (19 Aug, handled)
  Colab installs whatever transformers is current, and 'warmup_ratio' had been
  removed. Section 7 of the notebook now asks the installed TrainingArguments
  what it accepts and drops the rest.

LESSONS WORTH KEEPING
  - Never round a number that is used as a threshold.
  - Judge a retrained model by its SORTING SCORE, not accuracy at the default
    line. The app does not use the default line.
  - When you add data to one side only, run a control that mimics the side
    effect without adding information. For the fakes that was "copy the old
    ones". For the reals it needed TWO controls, because adding non-Reuters
    reals also dilutes Reuters' share — so one control copied real articles
    (same class balance) and one DELETED Reuters articles (same dilution).
    Both came in under +0.7 while the real thing moved +5.54.
  - Always ask: could this improvement be mimicked by a deletion? If yes, test
    that before believing the addition earned it.

THE COLLECTIONS AND WHICH FILE IS WHICH
---------------------------------------
  ISOT      = Fake.csv + True.csv                  <- TAUGHT ON
              True.csv is 100% Reuters wire copy. That was the flaw.
  diverse_fakes.csv                                <- TAUGHT ON, all FAKE
  diverse_reals.csv                                <- TAUGHT ON, all REAL
  McIntire  = fake_or_real_news.csv                <- EXAMINED ON

THE GOLDEN RULE: train on ISOT + diverse_fakes + diverse_reals, test on
McIntire. If anything from McIntire leaks into training, every number becomes a
lie. Both fetch scripts and the notebook screen for this automatically.

Why cross-source only: ISOT's real articles are all Reuters, so a model can
score 96-99.8% just by learning "writes like Reuters = real". Any score measured
on the same collection it trained on is worthless here.

WHAT THE APP DOES WHEN SOMEONE PASTES AN ARTICLE
------------------------------------------------
All in analyzer/analysis_engine.py, function analyze_text().

  STEP 1 — Exact fact-check lookup. Tidies the headline and looks it up in the
    KnownArticle table (44,931 articles: 38,720 ISOT, 6,211 McIntire). If found,
    answers from the database and stops. No model involved. This is why the
    model is only ever consulted on text from outside both collections.

  STEP 2 — The reading model (DistilBERT) in analyzer/reading_model/. Produces
    a score from 0 to 1 where higher means more likely fake, then compares it to
    the cutoff in analyzer/reading_model/cutoff.json (currently 0.400).

  STEP 2 FALLBACK — the old word-counter (analyzer/model.pkl +
    vectorizer.pkl), only if the reading model cannot load. Much worse: it
    ignores word order, so it cannot tell "scientists have proven" from
    "scientists have not proven". Keep it as a safety net, do not improve it.

SHARED HELPERS — do not reimplement these anywhere
  analyzer/text_cleaning.py    strips publisher fingerprints, e.g. the
                               "(Reuters)" dateline. Used by the training
                               scripts AND the live app.
  analyzer/text_matching.py    normalize_headline(). The ONE place headlines get
                               tidied. Both sides of the Step 1 lookup import
                               it; if they ever disagree the lookup silently
                               stops finding things.

HOW TO RETRAIN DISTILBERT
-------------------------
Not on the laptop. CPU training is 6-16 hours; a Colab T4 does it in 30-45 min.

  1. Put SIX files in your Google Drive folder 'fakedata':
       Fake.csv, True.csv, fake_or_real_news.csv, diverse_fakes.csv,
       diverse_reals.csv, and analyzer/text_cleaning.py
  2. Upload train_reading_model_v3.ipynb to Colab.
  3. Runtime -> Change runtime type -> T4 GPU.
  4. In section 3, make DRIVE_FOLDER match your folder name ('fakedata'). The
     file says 'fake_news_data'. THIS WILL BITE YOU EVERY TIME.
  5. Run sections 1-8 with TRIAL_RUN = True (~4 min). The number it prints is
     meaningless; it only proves the plumbing works.
  6. Set TRIAL_RUN = False in SECTION 5 (not section 9), then re-run sections
     5, 6, 7, 8 in order. Section 7 is the 30-45 minute one. Keep the tab open
     or Colab kills the session.
  7. Section 9 saves and downloads reading_model.zip (~250 MB).
  8. Back on the laptop:
       - copy analyzer/reading_model/ somewhere safe first
       - extract the zip into analyzer/reading_model/
       - DELETE the old cutoff.json and mcintire_scores.csv from that folder.
         They belong to the previous weights and would badly mislead the app.
       - python tune_cutoff.py
       - python manage.py test analyzer      (expect 60 passing)
       - python manage.py runserver
  9. Judge the result by the SORTING SCORE in section 8, which must beat
     95.39%. Ignore the accuracy figure there — it is read at the default line,
     which the app does not use.

ENVIRONMENT
-----------
Windows 11, git bash. PyTorch installed locally (~2.5 GB), which is what lets
the Django app run DistilBERT. Answering is fast on CPU, well under a second per
article. Only TRAINING needs a GPU.

A harmless startup note you will see: "model_meta.json not found". That is the
OLD word-counter's file (analyzer/model_meta.json), never in git, unrelated to
the reading model. Run python train_honest_model.py if you want it back.
